# OrdaX Network Gateway v2

Status: **SOURCE FOUNDATION / FAIL-CLOSED / NOT DEPLOYED**

This service owns the provider-neutral HTTP boundary for OrdaX Network
mutations. It is intentionally separate from Account Sync and from the
Owner/Development Control Plane.

Current source routes:

- `GET /network/v2/status`;
- `POST /network/v2/messages/send`.

The message route accepts exactly the sender Space, conversation id, client
idempotency key and bounded plain-text body. It rejects cross-site requests and
never accepts client-claimed user identity, roles, membership or authorization.

Authentication is injected through a server-side `NetworkSessionResolver`.
Provider credentials remain inside its opaque `authority_context`; the gateway
never serializes or logs them. The provider-specific `NetworkAuthority` must
revalidate the authenticated user against current Space/conversation authority.

The default resolver is anonymous and the default authority is disabled, so
source presence cannot activate Network.

## Supabase boundary

No Supabase adapter is implemented in this slice. The future adapter must use
the authenticated user's JWT/RLS context for the canonical Network v2 RPC. It
must not use a browser secret, `service_role`, or a client-supplied user id as
authorization.

The live v2 schema/RPC migration also remains blocked until it is generated by
the official Supabase migration workflow, checked with advisors, and passes the
existing ephemeral PostgreSQL proofs.
