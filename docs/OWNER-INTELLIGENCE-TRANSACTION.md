# Owner/Development — Intelligence in the existing Supervisor transaction

This optional, fail-closed Owner adapter stages the externally pinned Intelligence source **inside the same disposable Supervisor slot** already used for the exact OS commit and Surface. There is no second updater, identity authority, Memory, release signer or channel.

The canonical bridge templates live at `system/services/intelligence-source/wrappers/`. The Native build-time compositor `tools/intelligence-source/compose.py` reads those exact five files **from the OS input tree being assembled**, never from a separate checkout of the compositor; a missing or linked template fails closed. This binds bridge code to the same OS revision and prevents version drift or duplicate implementations; the Owner POSIX shell copies them from the signed/versioned OS candidate source into its disposable slot after validating the eight exact external Git blobs. Offline `ready` checks Git blob hashes, wrapper/template matches, the OS-commit template Git blobs and every file against a slot manifest. The live checkout and previous release remain untouched.

The existing Supervisor calls the adapter at staging, existing-slot reuse and canonical startup; its update mode forces a restart rather than unsafe hot reload when Intelligence is canonical. The adapter changes no behavior while `docs/contracts/intelligence-source.json` is `integration-candidate`. Before setting the source status to `canonical` and deleting the old tracked services, the Creator Owner/Dev **first cold boot must have a verified preseeded offline release slot**, and QEMU/USB health, updater, rollback and Buildroot availability must be proven. Otherwise the runtime cannot be promoted.

Stable/MVP uses signed v4 EROFS, not the Owner Git transaction. Its cutover and physical authorization remain independent gates, never inferred from the Owner tests.

## Creator preseed for offline first boot

The Creator Owner/Dev workflow assembles and validates the pinned Intelligence source as an isolated CI candidate. **While the source lock is `integration-candidate`, the bootable Owner slot is preseeded from the Surface-only release tree and retains the OS's existing Intelligence implementation**. It does not contain a provisional Intelligence source or engine wrappers. The preseed owner rejects an unpromoted external Intelligence tree rather than silently changing executable code at first boot. Only when the exact OS lock becomes `canonical` can Creator select the verified combined Surface + Intelligence tree and preload its source into the same Supervisor slot, generating `.intelligence-file-hashes` and `.intelligence-source-sha` and dropping the build-only Native receipt. `owner-stage.sh ready` validates that canonical prepared slot without network. The full Buildroot/Creator/USB tests must pass before changing that lock.

This is a future-ready offline slot and does not grant device control or start a second process. The OS still owns the immutable slot, activation/health decision and rollback.
