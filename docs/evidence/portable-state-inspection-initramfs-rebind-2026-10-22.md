# Portable activation inspection — canonical initramfs rebind (2026-10-22)

## Root cause and gate

PR #2149 extends the **existing** statically compiled `ordax-portable-state` helper
with a read-only `inspect` command. Its bytes are part of
`bootstrap/initramfs/initramfs.cpio.gz`. The Creator correctly blocked
assembling an updated initramfs against the previous, immutable SHA-256 pin.

The failing official workflow was
[Creator Payload Candidate #39810287111](https://github.com/ordaxsystems/ordax-os/actions/runs/39810287111)
at `Assemble and verify canonical complete Creator payload`:
`source artifact SHA-256 mismatch: bootstrap/initramfs/initramfs.cpio.gz`.
This is expected fail-closed behavior, **not** a reason to relax the assembler.

## Verified generated bytes

Both independent workflow paths for source commit
`46745c8dc63ac502518e6d07b65c0f6bf20ea8c2` reported exactly:

| Artifact | Previous canonical SHA-256 | Independently generated SHA-256 |
| --- | --- | --- |
| `bootstrap/initramfs/initramfs.cpio.gz` | `d95a62aa5b2cc2f287344a2792ce65911c57eab726a046d6de00da7a327695cc` | `add1985bd14155ed510848418e75ba224b345ab58531437a1300145b253279f9` |

The generated digest is reported by
[Initramfs Candidate #39810287231](https://github.com/ordaxsystems/ordax-os/actions/runs/39810287231)
and independently by the Creator job above. No kernel, signing key or
source-of-truth verifier was replaced.

## SSOT reconciliation

The verified initramfs pin is rebound in the already existing owners:

- `docs/contracts/minimal-bootstrap.json` — immutable Creator source artifact.
- `system/base-update/candidate.json` — exact Base A/B initramfs member.
- `tests/test_mvp_seed_artifact_bindings.py` — regression guard for the bound bytes.

Changing the bootstrap JSON bytes also changes the pre-consent exact binding.
The canonical repository file's SHA-256, verified directly after the rebind, is
`8c84e5325ff0c47f5b1d0104752fb73bab7315f0b2076ee6f46932c614ca884a`.
`docs/contracts/physical-write-authorization.json` is therefore rebound to
that digest alone; its `physical_write_allowed` and
`explicit_owner_authorization` remain **false**, and
`authorization_context_sha256` remains **null**.

## Limits

This is a source-artifact provenance reconciliation, not permission to write
any physical disk. The signed Stable/MVP release v4 authority and Base health
rollbacks remain separately gated. The Owner Dev transport stays `git-main`;
the new native inspection is strictly read-only, and the alternate signed
boot-profile handoff is still unimplemented. The PR must pass the official
Foundation, Creator, Base, and QEMU gates on the rebound commit before merging.
